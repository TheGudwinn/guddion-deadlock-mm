# Выпуск версии

## Один раз

1. Ключ подписи обновлений уже создан на этом компьютере в папке `%USERPROFILE%\.deadlock-mm\`:
   - `updater.key` — закрытый ключ;
   - `updater.password` — его пароль;
   - `updater.key.pub` — публичная часть (она вшита в `src-tauri/tauri.conf.json` → `plugins.updater.pubkey`).

   **Потеряете ключ или пароль — выпустить обновление для уже установленных копий будет нельзя.**
   Сделайте копию обоих файлов в надёжное место и никому не показывайте.
2. В репозитории GitHub: Settings → Secrets and variables → Actions → New repository secret:
   - `TAURI_SIGNING_PRIVATE_KEY` — содержимое файла `updater.key` целиком;
   - `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` — содержимое файла `updater.password`.
3. Репозиторий должен быть публичным, иначе приложение не скачает `latest.json` и пакеты без токена.

## Каждый релиз

1. Поднимите версию в трёх местах (должны совпадать): `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml`, `package.json`.
2. Закоммитьте и поставьте тег: `git tag v0.2.0 && git push --tags`.
3. Workflow `Release` соберёт Windows (NSIS с офлайн WebView2 и MSI) и Linux (deb и AppImage) и создаст
   **черновик** релиза с файлом `latest.json`.
4. Проверьте файлы, скачайте и поставьте установщик на чистой машине, затем нажмите **Publish release**.
   Пока релиз черновик, обновление пользователям не предлагается.

## Зеркало для обновлений

Приложение читает список адресов `latest.json` из настроек (по порядку). Чтобы обновления работали там, где GitHub
недоступен, выложите на любой https-хостинг файл `latest.json` и пакеты из релиза и добавьте адрес в Настройки →
Обновления. В `latest.json` поле `url` каждой платформы должно указывать на копию пакета на зеркале.
Подпись проверяется встроенным ключом, поэтому зеркало не может подменить сборку.

## Локальная сборка

```
.\scripts\build-local.ps1
```

Скрипт берёт ключ и пароль из `%USERPROFILE%\.deadlock-mm\`. Результат: `src-tauri/target/release/bundle/nsis/`.
Локальная сборка не знает адрес репозитория, поэтому источник обновлений в ней пуст; релизная сборка в CI
получает его из `DDMM_REPO`. Пустой пароль ключа использовать нельзя: сборка спросит его с клавиатуры и в CI зависнет.
